1. WHY
-------------------------------------------------------------------------------
The PI field is injected into every turn of every session: ~62,000 tokens
before any work starts. Measured composition (24 Sep 2026):

   Header — archived session narratives (34 PRIOR blocks)  114.7 KB  47.0%
   Working conventions (rules + incident stories)            44.0 KB  18.0%
   Library Register — full mirror                            32.2 KB  13.2%
   EX / AoT / RA / change-map programme narrative            21.1 KB   8.7%
   Vehicle                                                   10.5 KB   4.3%
   Design system                                              9.2 KB   3.8%
   Validation / model / source-of-truth / spec format         6.6 KB   2.7%
   Header — current session                                   2.7 KB   1.1%

Four costs: (1) context budget consumed before the work files are opened;
(2) live rules diluted by history, which also reads as current (probes have
already tripped on archived 'next free' strings); (3) internal duplication
drifts — LIVE CASE: the RA-1 block reads 'DONE 15 Sep 2026' although the
55th session corrected the weigh date to 10 Aug and records fixing it here;
(4) every figure mirrored from the Library Register must be fixed twice
(the 24 Sep register pass did exactly that).

PRINCIPLE: the field holds what should shape EVERY turn — rules, the
mastership map, protocol, current state. Everything else lives in a named
GitHub file the PI points to. A figure lives in its master, never here.
