  14 Oct 2026, owner ruling). Three rules that extend verify-before-you-report
  to the claims it did not name. They apply to every chat answer, every
  library edit and every research note. (a) A NEGATIVE CLAIM STATES ITS
  SEARCH. 'Not available', 'not sold in', 'no record', 'does not exist',
  'none found' is never written as a bare fact: it names where Claude looked
  and when ('not found on X, Y and Z, 13 Oct 2026'). A narrow search is
  widened before it is reported, or reported as narrow. Absence of evidence
  is not evidence of absence: a claim that something does not exist needs a
  wider search than a claim that it does. (b) A FACT THAT WILL DRIVE A
  DECISION CARRIES ITS BASIS — the source, what kind of source it is (maker's
  data, official notice, seller listing, forum post), and how sure Claude is.

  everything. Why: the seventy-eighth session's first Roadcruza check looked

  not sold in South Africa; a South African retailer existed, and the error
  was caught only because the owner checked. A negative closes the question,
  so it reads as a finding and invites no second look.

- Roll-forward reconciliation on governance files (standing, adopted 24 Jul
  2026; status check added 28 Jul). Reconcile a governance .txt edit the way a
  ledger is reconciled, not by checklist: BEFORE editing, snapshot the file's
  structural invariants; state the intended delta; recompute after; assert the
  difference equals exactly what was declared — anything unexplained is a
  finding. INVARIANTS — OIR: the multiset of section headers, the set of OI IDs
  with the section each occupies, the count of structural headers, the

  (line-start "OI-nn" followed by a title), not mentions, and read "next free"
  from the CURRENT header block only, never the last match in the file.
  (2) STATUS — extract every OI-nn in this file's HEADER NARRATIVE carrying an

  REGISTER WINS; keep a POINTER here, not the detail. When a probe disagrees
  with the file, suspect the probe first. LIMITATION: this catches SHAPE, NOT
  TRUTH — an invented number in a well-formed entry passes every assertion;
  verify-before-you-report is a different control. Why: the .txt files had no
  structural gate, and a duplicated "CLOSED LOG" header survived two commits.
- Idempotence, not just anchors (standing, adopted 24 Jul 2026). `assert count
  == 1` proves the ANCHOR is unique; it proves nothing about whether the edit
  has already been applied. When a replacement CONTAINS its own anchor, the
  guard passes on every re-run and silently duplicates the insertion. Any
  script that might be re-run must ALSO assert that a distinctive string from
  the NEW content is ABSENT before writing, and a post-edit count of that
  string should be 1. Recovery is a SHA-pinned re-fetch and a single clean
  application.
- Encode before you truncate (standing, adopted 24 Jul 2026). Never write an
  edited file with open(path,'w') — that truncates the target the instant it is
  called, so any later failure (a bad encode, a lone surrogate in an emoji, an
  exception mid-write) destroys the file before a single validation gate has
  run. Encode the full string to bytes FIRST, confirm that succeeded, then write
  binary. Only the write pattern can protect against this class; recovery is a
  single SHA-pinned fetch, which is one more reason pinning is not optional.
- Archives are not reconstructed, and a redacted archive says so (standing).
  The Open Items Register and LC76_Session_History.txt are ARCHIVES. Their
  narrative is never altered, removed or rewritten after the fact — a
  correction is an ANNOTATION against the original sentence, not a replacement
  of it. (i) Withdrawing a VALUE is a different act from altering a RECORD, but
  an archive that has been redacted carries a DATED REDACTION NOTICE naming the
  class of data withdrawn, stating that no narrative was altered, and noting
  that prior commits still hold the originals. (ii) A missing session is
  recorded as a LABELLED, DATED GAP and sessions are NEVER RENUMBERED to close
  it — renumbering would silently re-point every existing cross-reference. Why:
  a reconstructed record reads as contemporaneous when it is not (the F65 class
  applied to governance).
