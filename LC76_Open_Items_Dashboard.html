Every font size in the library is declared in rem, which resolves against the ROOT element. Every @media print block sets body. Body is not root, so for rem-sized text the print rule does nothing at all and never has. Printed pages have been coming out at screen size.

DIAGNOSTIC, 29 Jul 2026, depth-aware parse of all 71 HTML files at pinned HEAD: ZERO files set the root size in print; 1,547 rem font-size declarations sit in base CSS across the corpus. Severity varies by how far each file compensates with per-element overrides — 52 barely or not at all, 9 partial, 9 meaningful, 1 unaffected (the affidavit, which sizes nothing). The universal defect is all 71. REMEDY, PROTOTYPED IN LC76_How_To_Use_This_Library.html THE SAME DAY: one root declaration inside @media print, plus a shared block of rem heading overrides that COMPRESS the hierarchy (on screen a heading earns its size; on paper it need only be distinguishable). Because the overrides are rem and not pt, the root value is a single knob that rescales the document with relationships intact. No anchor hazard — nothing is replaced, only added.

OWNER GATE: body size ruled off a real printout before propagation. 12pt trialled and rejected as too large; 8pt adopted on the guide 29 Jul 2026 (knob = 11.6px). Micro-labels fall to ~5pt at that setting and the owner has accepted them.

PROPAGATION: Design Guidelines §16 must be corrected FIRST — it currently specifies the body-pt form that cannot work — then the template, then the corpus. The 9 partially-compensated files need their existing overrides reviewed as well as the root added, and are a separate, more careful pass.
