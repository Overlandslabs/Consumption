# LC76 SUPERSESSION LOG  —  the master list of real-world changes that retire a
# term in the corpus.  Read by lc76_currency_gate.py.
#
# WHY THIS FILE EXISTS (the point that keeps being missed):
#   The fact-gate catches NUMERIC drift.  Depth-walks catch STRUCTURE.  Nothing
#   caught stale PROSE — a part swapped on the vehicle (Racor->Flashlube) or a
#   status that turned (planned->fitted).  The only control for that is a
#   corpus-wide grep of the OLD term, run every session, re-grepped to zero.
#   A hand-kept list in a script fails the moment something NEW changes and
#   nobody remembers to edit the script.  THIS LOG removes that step: when a
#   real-world change happens you add ONE row here — the same old->new line you
#   would write to record the change anyway — and that row IS what arms the gate.
#   You cannot record the change without arming the check.
#
# LIMIT, STATED HONESTLY: this catches SUPERSESSIONS that go through the log.
#   It cannot catch a brand-new fabricated fact, or a change made in prose that
#   was never logged.  Log-first is the discipline; the gate is the rejecter.
#
# FORMAT — fields separated by '  ::  ' (double-colon); '|' is free for regex:
#   old_regex :: new_term :: tier :: as_of :: exempt_files :: exempt_line :: note
#     tier          fail = unambiguous stale (gate exits non-zero)
#                   warn = legitimate in some contexts (surfaced for review)
#     exempt_files  '|'-joined filename substrings to skip (- = none)
#     exempt_line   regex; a matching LINE is a legitimate use (- = none)
# Historical ledgers, changelogs and correction notes legitimately name the old
# term — that is what exempt_line / exempt_files are for.  Tune, don't delete.
